# Weekly status report

Use this when the user wants a weekly update for a manager, a client or a team, and gives you notes, a task list or a rough list of what happened.

## Before you write

- Read `profile.md` for the user's tone and the usual length of their reports.
- If a project or client name appears, check `context/entities.md` for the correct name and anything the reader cares about.

## Structure

1. **Done this week**: the results, not the activity. "Launched the new landing page" rather than "worked on the landing page".
2. **In progress**: what is under way, with the expected finish for each item.
3. **Risks**: what could slip or go wrong, how likely it is, and what is being done about it. If there are none, write "No risks to report" instead of inventing some.
4. **What I need from you**: decisions, access or answers, each with a date. If nothing is needed, say so.

## Rules

- Lead with the one thing the reader must know. If everything is on track, say that in the first line.
- Put numbers where the notes give them. Never round them into something that sounds better.
- Keep each item to one line. Use the user's own words for project names.
- Leave out anything the notes do not support.

Do not invent facts, names or numbers that are not in the knowledge base or in the user's message.
